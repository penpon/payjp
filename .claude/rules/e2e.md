# E2E（Playwright）方針

`CLAUDE.md` の仕様正本階層と整合する。**ユーザーから見える振る舞い**を検証する層として書き、実装の内側に張り付かせない。

## 正本（テストの「期待」の根拠）

1. `2weeks-spec.md` — 機能仕様・Go-Live 判定
2. `implementation-design-mvp.md` — API 契約・画面遷移の前提
3. `tdd-acceptance-matrix-mvp.md` — T-P0-01〜T-P0-07 受け入れ

仕様とズレた E2E は修正対象ではなく、**仕様か実装のどちらを直すか**を判断する材料にする。MVP 非スコープ（管理画面・DLQ・高度監視など）を E2E で増やさない。

## 手動確認と E2E の順序

- **初回や大きな UI/フロー変更の前**は、主要クリティカルパスを手動で一度通し、期待する文言・遷移・エラー表示を確かめてから E2E に落とす。
- E2E は **「すでに合意された振る舞い」の安全網**。実装都合だけでセレクタや待ち方を決めない。

## 書き方（メンテしやすくする）

**優先する（仕様に紐づきやすい）**

- アクセシビリティに沿った取得: `getByRole`, `getByLabel`, ユーザーに見える名前・ラベル
- 安定したテスト用フックが必要なら **`data-testid`** など、意図が明示される属性（乱用はしない）
- Playwright の **自動待機**を前提にし、状態は `expect` で明示（表示・URL・ネットワーク完了など）

**避ける（実装変更で壊れやすい）**

- CSS クラス名や DOM の深さだけに依存したセレクタ
- 内部 API の呼び出し順・実装詳細の検証（それはユニット/統合側）
- 安易な **固定 `sleep`**（フレークとメンテコストの元）
- **1 テストにシナリオ詰め込み**（失敗時に原因が分かりにくい）

## スコープ

- **クリティカルパス**（ログイン〜購読〜失敗時メッセージ等）を優先し、細かい分岐は下位テストで押さえることが多い。
- 変更が頻繁な見た目の微差まですべて E2E で固めない。

## セキュリティ・環境（`security.md` と併読）

- `.env*` の読み取りやシークレットの埋め込みをテストコードに持ち込まない。
- Cookie（`__Host-*` 等）の属性をテスト都合で弱めない。ローカル E2E の前提は **`playwright.config.ts`** に従う。

## 実行・設定

- コマンド: `npm run e2e`（ルート `package.json`）
- ブラウザ起動オプション・baseURL・webServer は **`playwright.config.ts`** が正。変更時はこのファイルと本書の意図を両方更新する。
